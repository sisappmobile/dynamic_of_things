While implementing server-side pseudo_code execution (Option B) for BEO's detail form "Produk Transaksi" (c_custom_form id 2751043, header id 2749043), we hit and worked around a fundamental architectural constraint: **`Field.readOnly` lives on a single, per-COLUMN `Field`/`FieldCustomFormView` object shared across every row of a LIST-mode detail form — there is no per-row Field instance.** A pseudo_code/script `FOR element IN <table> ... element.<field>.readOnly = ... ENDFOR` loop over N>1 rows leaves only the LAST-processed row's value on the shared Field ("last row wins"), silently leaking one row's condition onto every other row's display.

**Why:** [dynamic-of-things-architecture.md](dynamic-of-things-architecture.md)'s detail-form model (both the Dart client `Template`/`Field` classes and the Java `HeaderForm.Template.valueOf`) was designed around one Field object per table column, not per cell — readOnly/mandatory are column-level JSON properties in the API contract, same on both `custom_dynamic_form.dart`/`PseudoCodeEngine.java` sides.

**How to apply — the pattern that works, confirmed by the user:**
1. Client-side: when a detail-row editor (`CustomDynamicFormDetailForm`) opens, the caller (`custom_dynamic_form_detail_list.dart`) scopes `headerForm.data[tableName]` down to a one-element array containing just that row (restored after the editor closes, committing on Save / discarding on Cancel). The editor also auto-fires a scoped `DynamicFormRefresh` the moment it opens (via its own locally-owned `DynamicFormBloc` instance, not `context.read` in `initState()` since that looks above the widget's own `build()`-returned tree) so the row's own readOnly/computed state is always freshly re-derived on open, self-healing any staleness left by an unrelated all-rows refresh.
2. Content-side: do NOT try to guard shared cross-row calculations (header totals like `total_diskon`/`subtotal_transaksi`/`total_transaksi`/`sisa_tagihan`) with an `IF <table>.size == 1` check if they live in the SAME pseudo_code as per-row readOnly toggles — that would break totals recomputation on the header-level "after save" refresh (which legitimately needs to scan all rows). The user's resolution: consolidate ALL the real logic (header field derivations like `status` from `DATEDIFF`, detail-row readOnly toggles, per-row value calcs, and cross-row totals) into ONE pseudo_code script attached to a single field, and put a dummy `BEGIN\nEND` pseudo_code on every OTHER field that needs to trigger a refresh (so `hasScript`/`field.hasOnChangeEvent` becomes true and its onChange dispatches `DynamicFormRefresh`) — the collector on both engines dedupes by exact script text and runs every distinct script found, so the one real script always executes regardless of which field triggered the refresh.

**DSL gotchas discovered along the way** (apply to both `json_script_engine.dart` and `dmsretail`'s `com.sisapp.helper.PseudoCodeEngine`/`PseudoCodeException` — keep any future engine fix in lockstep across both, or the two interpreters diverge):
- Plain `=` assignment does NOT evaluate comparison operators (`==`, `!=`, etc.) — only `IF`/`REQUIRE`/`ASSERT` conditions do. Use `IF cond ... element.x.readOnly = true ... ELSE ... ENDIF`, never `element.x.readOnly = a == b`.
- `element.<field>.readOnly = <bool>` (2 path segments after the loop var) is special-cased to mutate the FieldCustomFormView/Field's readOnly metadata directly; `element.<field> = <value>` (1 segment) is a normal data-value write. These don't collide.
- CHECK-type fields round-trip as `"Y"`/`"N"` strings end-to-end (`DynamicForms.encodeValue` on the Flutter side, `DynamicFormHelper.mapToHashDTO` passthrough on the Java side) — comparing them against a `true`/`false` literal needs loose boolean coercion (`_looseEquals`/`equalsLoose`), otherwise `String == Boolean` is always false with no error, silently breaking the branch.
- `DynamicForms.encode()` used to mutate detail/sub-detail row Maps in place while building the wire-format request payload, corrupting live UI-bound data (e.g. a `bool` flipped to `"Y"` mid-edit) — fixed to deep-copy rows before encoding.
- A `/refresh` script/pseudo_code failure returns HTTP 202 (`GeneralResponse{RC:1, RM:"..."}`), not 4xx — `DotApis.dynamicFormRefresh()` used to silently return null on any non-200 status, swallowing the error with zero visible symptom. Fixed to throw with the server's `RM` message so it surfaces via the bloc's existing catch-and-toast/log path.
